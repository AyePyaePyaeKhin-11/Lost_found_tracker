# Nuun: Core database and item CRUD

This package was built against commit `5c99c8f` from the uploaded review ZIP.
It changes `database.py`, `app.py`, and adds `routes/items.py` plus a smoke check.
Use it on `feature/nuun-core-items` only after `git status` shows a clean tree.

## The data flow

`POST /api/items` -> FastAPI `ItemCreate` checks the request -> `current_user`
checks the JWT and finds the user's organization -> parameterized SQL `INSERT`
adds a row to PostgreSQL -> `RETURNING *` sends that row back as JSON.

`organizations` is the tenant table. Existing and newly registered users are
assigned to the KMITL row in the current single-campus prototype. Every item
has an `organization_id` and `reported_by`. Item reads and edits require the
same organization. Only its reporter or an admin may edit/claim/archive it.

The `item_id` is a UUID generated by the API unless supplied by a client.
Supplying an existing UUID returns 409. Validation errors return 422.
Archiving changes status rather than physically deleting a row.

## Install on your Mac

1. Download the accompanying ZIP to `~/Downloads/Nuun_Core_Items.zip`.
2. Run these commands (one block) in Terminal:

```bash
cd "$HOME/Documents/GitHub/Lost_found_tracker"
git switch feature/nuun-core-items
git status --short
unzip -o "$HOME/Downloads/Nuun_Core_Items.zip" -d .
git diff -- acpapp/backend-api/database.py acpapp/backend-api/app.py
git status --short
```

Read the displayed diff before committing. If your branch has other work,
compare it first because `unzip -o` replaces the two existing files.

## Run the project and check the result

From the repository root:

```bash
cd "$HOME/Documents/GitHub/Lost_found_tracker/acpapp"
docker compose up --build -d
docker compose ps
python3 backend-api/tests/smoke_items.py
```

The last command should print PASS for auth, invalid data, insert, duplicate
ID, listing, ownership, update, and claim. Open `http://localhost:8000/docs`
to try the API by hand. Run `docker compose logs backend-api --tail=80` if the
service fails to start. Existing `/api/products` demo endpoints still refer to
a `products` table that this project's starter did not create.

## Scope and limitations

The attached starter uses raw SQL; it does not use the Alembic/ORM structure
described in the proposal. Table setup runs at backend startup and adds columns
to an existing starter `users` table. This implementation does not create the
teammates' `matches` or `transactions` tables. The claim route checks reporter
or admin ownership; confirmation of a match can be integrated once that
package exists. The current JWT secret remains the starter's secret and should
be handled by the auth teammate before deployment.
